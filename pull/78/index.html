    Kuiper Imager

    Kuiper Imager prepares a bootable Analog Devices system on an SD card in one guided flow. Before the details, it helps to know what it is writing.

    What is a Kuiper image?

    ADI Kuiper Linux is a Debian-based Linux distribution from Analog Devices (currently built on Debian Trixie), designed specifically for its hardware and evaluation boards. It is distributed as SD-card images that bundle the ADI Linux kernel with a Debian system, so you boot straight into a Linux that already knows the hardware instead of building one by hand.

    A Kuiper image comes in two editions and two architectures:

    • Basic — a minimal system: the ADI Linux kernel on a Debian base, with no desktop and no ADI libraries or tools. Suited to headless use.

    • Full — the Basic system plus an XFCE desktop (with a VNC server for remote access) and the ADI software stack: libiio and the pyadi-iio Python bindings, libm2k, the IIO Oscilloscope, Scopy, GNU Radio, and more.

    • 64-bit (arm64) and 32-bit (armhf) builds, matching the processor on your board.

    The two editions differ only by which features were enabled when the image was built, so customize can add the Full-image features to a Basic image after the fact.

    What is it used for?

    You use a Kuiper image to bring up an Analog Devices evaluation board and run or develop software against it. Kuiper supports Raspberry Pi, AMD/Xilinx (Zynq, ZynqMP, Versal — e.g. ZedBoard, ZCU102, VCK190), and Intel/Altera (Arria 10, Cyclone 5 — e.g. DE10-Nano) platforms. Writing a Kuiper image to the card gives you a Linux that already knows the hardware — so you can scope signals in the IIO Oscilloscope, drive the part from libiio, or prototype in Python.

    A Raspberry Pi image boots out of the box. An ADI evaluation board must be configured first — the image needs the correct boot files for your exact board-and-carrier combination before it will boot — which is precisely the step Kuiper Imager automates below.

    How Kuiper Imager helps

    Preparing a card by hand has meant juggling several tools and a set of easy-to-get-wrong steps — finding the right image, writing it safely, and then copying the correct boot files for your exact board-and-carrier combination. Kuiper Imager replaces that with one application and a guided Fetch → Flash → Configure workflow:

    Fetch

    List official and CI-built Kuiper releases and download the one you want.

    Flash

    Write an image to an SD card or drive, with progress and read-back verification so you know the bytes on the card match the image.

    Configure

    Copy the correct kernel and boot files for your specific eval-board and carrier combination — the most error-prone manual step, done for you. (Raspberry Pi cards boot without this step.)

    Each command ends by suggesting the next, so a first-time user is walked from a blank card to a booting board, while the steps stay independent for anyone who only needs one. A fourth operation, customize, turns a basic image into a full one by installing the ADI features you pick.

    Kuiper Imager is CLI-first: all the logic lives in a UI-agnostic core library (libkuiper) that the kli command-line tool and the Qt desktop GUI both drive in-process, so the two front-ends behave identically. The GUI suits most users; the CLI suits scripting, automation, and headless servers. Flashing writes to raw devices, so it guards against erasing the wrong disk: the running system disk can never be a target, and every write is verified by reading the card back. See Architecture Overview for how it all fits together.

    Platform support

    Kuiper Imager is version 2.0 and runs on Linux and Windows, with macOS planned. Capabilities differ by platform:

    Platform

    Status

    Linux

    Complete. list-drives, flash, list-projects / configure (including the Intel preloader), list-releases / fetch (stable and CI channels), customize, and the full GUI.

    Windows

    list-drives, flash (with verification), safe eject, list-releases / fetch, and list-projects / configure for ordinary (non-Intel) boards. The Intel preloader write and customize are Linux-only for now.

    macOS

    Planned. The drive backend is a compilable stub, so the structure is in place but imaging is not yet implemented (see Platform Backends).
